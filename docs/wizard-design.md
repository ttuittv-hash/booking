# BOOK IT 공용 디자인 규칙

2026-10-27 기준. 대관사 및 행사 정보에서 승인된 최종 규칙을 정본으로 한다. 과거 시안의 박스형 입력, 표 헤더선, 행 구분선 규칙은 폐기한다.

## 적용 범위와 책임

- `/apply`, `/apply/edit/[id]`, 로컬 `/apply/design-preview`는 동일한 테마를 사용한다.
- `WizardDesign.module.css`: 색상, 모서리, 간격, 제목, 필드 높이와 컨테이너 패딩 토큰.
- `BookingPreview.module.css`: 위 테마를 소비하는 화면 배치와 컨트롤 규칙. 달력, 옵션, 서명 등 기능별 배치는 구분한다.
- `bookingFormRules.ts`: DB 문구와 무관한 고정 레코드 ID와 칼럼 배분. 문구를 바꿔도 너비가 바뀌지 않는다.
- `BookingPreviewForms.tsx`: DocumentPanel, DocumentGroup, PreviewRecordTable. 데이터·검증 속성·삭제 콜백은 원본 폼에서 전달한다.
- `kit.tsx`: 선택형 CheckboxChip은 체크 아이콘 없는 aria-pressed 버튼이다. 법적 서약·전체 동의·파일 선택은 별개의 컨트롤이다.

## 표면·간격·계층

- 큰 섹션마다 별도의 흰색 컨테이너와 공용 12px 모서리를 사용한다. 섹션 구분은 간격으로 표현한다.
- 패널 패딩 24px, 입력 그룹 세로 간격 28px, 왼쪽 제목 칼럼 150px, 제목과 입력 간격 24px.
- 모바일에서는 제목을 위로 올리고 패널 패딩을 공용 모바일 토큰으로 줄인다.
- 중첩된 legacy mt/pt가 패널 상단에 누적되지 않게 한다.
- 설명은 해당 제목 아래에 둔다. 전체 섹션 안내·법적 고지는 특정 선택항목의 설명으로 이동하지 않는다.
- 제목 → 섹션 → 입력 그룹 → 필드 레이블의 위계를 유지한다. DB의 숨김·빈 문구 설정을 임의로 복원하지 않는다.

## 입력 규칙

| 역할 | 표시 |
| --- | --- |
| 일반 text/number/date/textarea | 밑줄만 사용. 빈 값은 옅은 회색, 입력 후 흰색. 왼쪽 padding 0으로 레이블과 정렬 |
| select | 밑줄 유지. 닫힌 선택값은 왼쪽 여백 0, 펼친 옵션은 좌우 12px(네이티브 메뉴는 운영체제 기본 여백) 유지. 오른쪽 chevron 공간 확보. 포커스 사각 외곽선 없이 밑줄로 상태 구분 |
| 자동 계산값 | readonly 회색, 공용 모서리, 좌우 12px padding. 값과 ‘자동 반영’을 같은 줄에 표시, 상태는 오른쪽 정렬 |
| 선택 칩 | 체크박스 없는 사각 rounded 버튼. 선택 시 검정 바탕. aria-pressed와 disabled 전달 |
| 동의·서약 체크 행 | 선택 칩과 구분. native checkbox와 label 연결, 전체동의·종속동의·서명 검증 유지 |

수량 조절기·달력 날짜·파일 업로드·서명판은 전용 기능 구조를 유지한다. 밑줄 입력 규칙을 이들 내부 컨트롤에 무차별 적용하지 않는다.

## 칼럼·반복 입력

- 왼쪽 제목을 제외한 기본 입력 영역은 6칸과 작업 칼럼을 기준으로 배치한다.
- 단독 필드와 표의 시작선을 맞춘다. 표 내부 입력 텍스트와 헤더 시작선도 일치시킨다.
- 반복 표는 헤더 1개, 헤더 아래선 없음, 행 사이선 없음. 입력 밑줄만 표시한다.
- 삭제는 작업 칼럼 중앙. 접근성 이름은 제공하되 ‘관리’ 제목은 시각적으로 숨긴다.
- 넓은 기록은 단위당 최소 104px로 확장하고 해당 표 안에서만 가로 스크롤한다. 페이지 전체는 넘치지 않는다.
- 최신 배분은 `RECORD_LAYOUTS`가 정본이다. 연락처·객석·관객 수·판매율은 1칸, 소속·이메일 등은 2칸, 긴 공연명·이력은 3~4칸.
- 날짜 입력을 칼럼 끝까지 배치하고 ‘미정’ 버튼은 데스크톱에서 작업 칼럼으로 분리한다. 모바일에서는 안전하게 함께 줄바꿈한다.

## 동작·문구·데이터

- 신청자 정보 섹션은 01 대관사와 담당자 → 02 공연·행사 → 03 관객·프로모션 → 04 개최 신뢰성 순서다. 하나를 열면 이전 섹션은 닫힌다.
- 화면 구조 변경은 선택값, 필수 검증, 초안 저장, 첨부, 제출 API를 변경하지 않는다.
- `redesigned`는 표현만 선택한다. `designPreview`만 로컬 저장·가상 제출을 사용한다.
- 운영 문구는 `getScreenTextContent()`에서 읽은 DB 설정을 우선한다. 로컬 `previewScreenText`는 샘플이다. 신규 고정 제목/레이블의 DB 키 연결은 배포 전 별도 확인한다.
- `/apply/design-preview?review=1`은 개발 전용, 단계별 검수용이다. 검증 게이트를 통과한 실제 신청으로 취급하지 않으며 기존 초안을 저장하거나 변경하지 않는다.

## 검증 및 릴리스

공용 컴포넌트의 의미·접근성·검증 속성 전달과 너비 설정을 테스트한다. 각 화면은 데스크톱과 모바일에서 직접 확인한다. 로컬 검수는 실제 DB 저장/파일 업로드/알림 통합 검증을 대신하지 않는다. 사용자 승인 없이 푸시·배포하지 않는다.

- 견적 할인 금액은 `-₩51,830,000` 순서로 표시하고 마이너스 기호·통화 기호·숫자 전체에 danger 색상을 사용한다.

- 최종 검토의 첨부파일 링크는 공용 보조 버튼(흰 배경, 경계선, 6px 모서리)을 사용한다. 대체 일정 동의는 공용 그룹 배경·8px 모서리·그룹 패딩을 사용하며 동의 로직은 유지한다.
