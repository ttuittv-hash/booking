# 관리자 공통 디자인 기준

실제 `/admin` 화면의 기준이다. 공개 페이지와 신청 위저드는 이 기준을 사용하지 않는다.

## 적용 경로

`src/app/admin/layout.tsx` → `adminDashboard.css` → `.admin-page` 내부의 공통 클래스.
`adminUi.ts`는 공통 클래스 이름을 내보내며 화면은 이를 사용한다.
실제 화면과 미리보기는 같은 공통 시각 기준을 사용한다. 페이지별 CSS는 배치와 전용 편집 동작만 담당하며 공통 치수는 아래 소유 파일의 변수를 참조한다.

## 기준값

| 항목 | 기준 |
| --- | --- |
| 페이지 제목 | 30px, 모바일 26px, 굵기 800 |
| 섹션 제목 | 18px, 굵기 700 |
| 본문 | 13px |
| 패널 | panel 배경, 반경 12px, 여백 24px / 모바일 18px. 기본 목록 패널은 무테두리, 편집·리포트 패널은 border-soft 1px 변형 |
| 입력창 | 기본 44px, 작은 입력 32px; 흰 panel 배경, field-base 동작 상속 |
| 일반 탭 | 높이 56px, 활성 검정 3px 밑줄, 비활성 muted |
| 삭제 | danger 색의 텍스트 버튼 |

크기·여백·모서리는 `adminDashboard.css` 상단 `--admin-*` 값에서 수정한다.
패널과 탭을 화면별 Tailwind 유틸리티로 중복 정의하지 않는다.
사이트 색상은 globals.css의 시맨틱 색상 토큰을 상속한다.
세그먼트 탭과 상세 화면별 전용 컴포넌트는 별도 변형이다.

## 스타일 소유권

- `adminDashboard.css`: 어드민 범위의 색·반경·글자·패널·필드·표·탭 기준 및 차트 색 변수.
- `adminButton.ts` / `AdminButton.module.css`: 실행 버튼의 px 크기·반경. 공개 kit의 색상·disabled·focus 동작을 재사용하되 공개 kit 자체는 수정하지 않는다.
- `AdminEditor.module.css`: 편집용 패널 변형, 구역별 저장/추가 슬롯. 저장 버튼은 AdminButton의 medium 규격을 compose한다.
- 페이지별 CSS: 배치·스크롤·도구 위치 및 의미가 다른 전용 변형. 공통 텍스트 크기와 반경은 어드민 변수를 참조한다.
- 기존 Tailwind 카드에 적용하는 adminDashboard의 호환 선택자는 `.admin-page` / `.admin-design-scope` 내부로 제한한다. 공개 사이트 전역 선택자로 확장하지 않는다.
- 기능 조회는 실제 화면에 연결한다. 미리보기의 예시 데이터는 운영 DB를 대체하지 않는다.

## 복잡한 편집 화면 (패키지·요금표·콘텐츠)

`AdminEditor.module.css`의 workspace는 상위 관리자 토큰을 참조한다: 편집 카드 12px, 입력창 6px, 여백 24px/모바일18px, 입력 높이 44px.
`AdminEditorSection`은 제목·설명·접기/펼치기를 공통 제공한다. 접힌 입력도 마운트 상태를 유지해 편집값을 보존한다.
공개 노출 정보와 내부 참고를 구분하며, 업무 기능이나 저장 로직을 미리보기 전용 구현으로 대체하지 않는다.
1차 대표 적용: 실제 PackagesForm의 기본 정보, 공개 안내 문구, 내부 참고. 다른 영역은 검토 후 확장한다.

### 옵션 목록과 상세 편집

`AdminOptionCatalog`는 카테고리 개수·검색·포함/노출 필터와 수량/단가 비교 목록을 제공한다. 항목 상세는 기존 편집 컨트롤을 전달받아 기능을 보존한다. 1100px 이상에서는 목록 옆 패널, 작은 화면에서는 아래 패널로 배치하며 표만 가로 스크롤한다. 상위 시각 규칙은 `AdminEditor.module.css`에서 관리한다.

패키지의 기본 설정과 옵션 작업을 분리한다. 노출 분류(기본 포함/내부 비용/선택 옵션)와 항목 카테고리(공간/시설/프로덕션 등)는 별도 탐색 축이다. 현재 아레나·올인원 경로에 적용했으며 중형 전용 편집은 유지한다.

### 탐색 단계의 시각적 구분

패키지 선택은 독립 카드의 선택 버튼, 작업 영역은 설명이 있는 밑줄 탭, 노출 유형은 묶음 선택, 항목 카테고리는 개수 표시 필터로 구분한다. 패키지 순서/복제/삭제/추가는 선택 카드의 '패키지 관리'에 모은다. 옵션 추가는 카테고리 마지막 '+ 항목 추가'에서만 펼치며 새 항목 생성과 기존 항목 가져오기를 보존한다. 규칙은 AdminEditor.module.css에서 관리한다.

### 요금표 편집

요금표는 공간 선택 아래 설명형 작업 탭(부대시설 단가/공통 요율)을 둔다. 단가 목록은 패키지와 같은 카테고리 필터·검색·추가 패널·표 규칙을 재사용한다. 단가 입력은 왼쪽, 삭제는 오른쪽 끝에 둔다. 실사용 정산 항목은 단가 편집 불가를 명시한다. 실제 저장 요청 구조는 유지한다.

### 중형공연장 편집과 보조 설명

중형공연장은 기본 포함 내역/추가 비용 안내/선택 가능 옵션으로 작업을 구분한다. 안내는 열 제목이 있는 표, 수량형 옵션은 공통 AdminOptionCatalog를 재사용한다. 체크 설정은 체크+제목+i로 표시하고 AdminHelpTooltip으로 hover 및 키보드 focus 시 설명을 제공한다.

### 콘텐츠 편집 공통 규칙
- 목록형 필드는 공용 ListEditor에서 제목 목록과 펼침 편집으로 제공한다. 긴 폼은 한 항목씩 펼치며 추가된 항목은 즉시 펼친다. 이동·삭제는 유지한다.
- 본문 입력은 공용 Area를 사용한다. 줄바꿈/새 문단 안내는 화면 상단 한 번만 표시한다. 입력별 도움말은 고유한 설명에 한정하며 구분선을 사용하지 않는다. 실제 렌더러가 지원하는 본문에만 굵게 도구를 제공한다.
- 파일 입력은 FileUpload로 통일한다. 브라우저 기본 Choose File 대신 파일 업로드 버튼을 표시하고 키보드 포커스를 유지한다.
- 분할 ON/OFF는 가운데 직선, 바깥쪽 끝만 공통 control radius를 적용한다.
- 게시물 카드는 배경/그림자 hover 및 focus-within 피드백을 공유하고 reduced-motion을 준수한다.

- 콘텐츠 최상위 카테고리와 요금표·일정 공간 탭은 AdminEditor.venueTabs 규칙을 공유한다: 56px 최소 높이, 3px 선택 밑줄, 28px 간격, 14px 글자, radius 0. 콘텐츠 전용 카테고리 탭 CSS는 두지 않는다.

### 콘텐츠 편집 수정 (2026-10-23)
- 일반 텍스트 Area의 굵게 도구는 제거. `**강조**` 수동 표기 안내를 제목 위 공통 위치에 제공한다.
- ListEditor 그룹과 각 이동/편집 항목은 서로 다른 배경의 rounded 컨테이너로 구분한다.
- ON/OFF 반쪽은 자체 반경 없이 바깥 트랙의 overflow clipping만 사용한다.
- 공지 리치텍스트는 NoticeEditor 공용 스타일에서 단일 rounded 외곽과 sticky 툴바/본문 경계를 관리한다. 글자 설정과 정렬은 hover/focus 메뉴이며 기존 삽입 기능은 보존한다.

- 닫힌 분류는 native select로 제공하여 선택 화살표를 표시한다.
- 목록의 접기는 최상위만 적용하며 중첩 ListEditor는 바로 편집한다. 접힌 헤더에는 하단 margin을 두지 않고 열린 본문에만 간격을 준다.
- 공지 서식은 직접 글자 크기/초기화 없이 색상 팔레트만 제공하고 정렬은 아이콘 메뉴로 통일한다. HTML 모드 전환은 편집기 외부에 둔다.
- 규약 문서 편집은 기존 텍스트/표 직렬화와 기능을 유지하며 공지와 같은 외곽/툴바 스타일을 공유한다.

### 위저드 콘텐츠 편집
- 신청자 화면은 동일한 위저드 컴포넌트를 격리된 미리보기에서 렌더링한다. 편집 도구·점선 밑줄·속성 목록을 신청자 화면에 삽입하지 않는다.
- 제목/안내, 화면 문구/입력 안내, 항목 구성/순서/노출을 별도 편집 패널에 배치한다. 단계와 시설 선택은 미리보기와 연동하며, 단계 이동으로 미저장 콘텐츠를 초기화하지 않는다.
- 관리자 프레임은 ADMIN 인증을 요구한다. 신청 제출·첨부는 미리보기 동작으로 격리한다. 실제 신청서 임시저장소를 사용하지 않는다.
- 규약은 기존 평문/표 직렬화 형식을 유지한다. 표 삽입은 공통 격자 선택기, 행/열 조작은 표 가장자리에서 제공한다. 표 전체는 닫힌 테두리와 공통 패널 반경을 사용한다.
- 화면 문구 편집은 사용 위치별 목록과 선택 영역 편집으로 구성하고 내부 식별자는 기본 라벨에 노출하지 않는다.

### 알림 관리
- 입력 배경은 adminDashboard.css 공통 규칙의 panel(흰색)을 상속한다. 페이지 전용 배경 덮어쓰기를 금지한다.
- 트리거 카드는 AdminEditor.section/title, 탭은 venueTabs, 목록 하단 추가는 AdminEditor.tableAdd, 항목 저장은 saveBar/saveButton(구역 하단 우측, 44px)을 사용한다. 페이지 CSS는 배치와 간격만 담당한다.

### 1:1 문의
- 목록 및 상세 패널·표·상태 표시는 실제 관리자와 미리보기에서 공통 클래스를 공유한다.
- AnswerInquiryForm은 AdminEditor 제목/설명 및 saveBar/saveButton, adminUi FIELD/PANEL을 사용한다.
- 문의 페이지 이동은 공용 Pagination을 사용한다. 한 페이지일 때 이동 버튼 없이 전체 건수를 표시한다.
- 사이드바 문의 숫자는 전체 OPEN 문의 건수이며, 0건이면 숨긴다. 답변 등록·페이지 이동·창 복귀 시 갱신한다.
- 공용 Pagination 번호는 박스 없는 텍스트로 표시하며 현재 페이지는 굵기만으로 구분한다. 번호 최소 폭은 24px, 간격은 4px이다. 이전/다음은 btnClass secondary/sm(데스크톱 32px, 모바일 44px)과 공통 control radius(6px)를 그대로 사용한다.

- 페이지 이동과 표 사이에는 가로 구분선을 넣지 않고 여백만 사용한다. 문의 목록은 행 전체 클릭으로 상세를 열며 키보드용 제목/상세 링크를 유지한다.
- 관리자 일정의 확정/심사 상태는 개별 배지 대신 날짜 칸 전체 배경과 상태별 건수 텍스트로 표시한다. 혼합일은 확정 배경에 양쪽 건수를 표시하고, 대관 불가 배경은 우선 유지한다.
- 콘텐츠 구성도 선택은 기존 배경 위 파란 틴트와 연한 파란 외곽선을 사용한다. 연결 편집 영역 헤더도 옅은 파랑으로 표시하고 검정 배경/글자 대비는 유지한다.
- 일정 범례는 컬러 원으로 표시하며 기본 아레나 심사일은 연한 노랑 배경과 짙은 노랑 텍스트로 구분한다.

### 리포트
기간 선택은 ContentTabs 공통 세그먼트(흰 바탕, 회색 선택)를 재사용하며 별도 흰 컨테이너를 두지 않는다. 보고서 카드와 수치 안내는 관리자 panel/control 반경을 사용한다. 막대 차트 행은 오프화이트 hover와 키보드 focus를 제공하고, 모바일에서는 항목명/수치 아래에 막대를 배치한다. 차트 계열 색은 범례와 일치하게 유지한다.

### 관리자 버튼 소유권 정리 (감사 후속)
- 관리자 전용 `adminButton.ts`와 `AdminButton.module.css`가 실행 버튼의 크기와 반경을 소유한다. 공개 사이트의 `ui/kit.tsx`는 수정하지 않는다.
- sm은 데스크톱 32px/모바일 44px, md는 44px, lg는 48px, 반경은 공통 6px다. rem으로 인해 화면 폭마다 실행 버튼이 축소되지 않는다.
- 색상·hover·disabled는 기존 kit 의미를 유지한다. 설정뿐 아니라 관리자 폼·목록·리포트·계약·정산·심사·팝업의 실행 버튼에 적용한다. 공용 페이지 이동은 /admin 경로에서만 이 규격을 선택한다.

### 실제 신청 목록과 리포트 검증 기준
- 회사 드롭다운과 검색어는 별개 조건이며 함께 적용할 수 있다. 검색 문자열의 `%`·`_`는 일반 문자로 취급한다.
- 신청번호·회사/신청자·공간/패키지·일정·계약금액·상태는 서버에서 전체 결과에 정렬한 뒤 페이지를 나눈다. 기본은 신청번호 최신순이며 정렬 변경 시 1페이지로 이동한다.
- 공간이 같으면 신청 당시 요금표의 패키지 배열 순서를 따른다. 금액 정렬은 표시하는 계약금액(VAT 포함)을 따른다.
- 운영자 계정 바로가기는 MASTER에게만 표시한다. PRO는 등록 요청 안내를 본다.
- 매출 카드 숫자는 한 줄로 표시하고, 컨테이너 폭에 따라 4/2/1열로 배치한다. 도넛의 승인된 중간 밝기 색상은 상위 어드민 차트 변수에 둔다.
